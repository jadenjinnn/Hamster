## Problem

The current editor UI was built with development speed in mind — layout and spacing are functional but inconsistent. Section headers, labels, and values lack typographic hierarchy (everything reads at the same visual weight). The asset browser uses a flat layout instead of the grid-of-cards style shown in the design mockup. The property editor, hierarchy, and level editor viewport all need spacing and styling refinement to feel cohesive and polished. This matters because the editor is the primary showcase artifact for the project.

## In scope

- **Typographic hierarchy across all panels**: bold section headers, clear weight/size distinction between headers, labels, and values
- **Property editor layout**: better spacing and grouping between component sections (Transform, Sprite, etc.), consistent field alignment
- **Hierarchy panel styling**: tree indentation, selection highlight polish, visual refinement
- **Asset browser grid**: large thumbnail/icon cards with labels underneath, replacing the current layout
- **Level editor viewport**: padding/spacing around the viewport edges, zoom slider visual styling
- **Consistent spacing**: uniform padding, margins, and section gaps across all panels

## Out of scope

- New panel functionality (no new buttons, menus, or features)
- Play/stop button redesign (keeping current square style)
- Scene viewer changes (dot grid, axis gizmo, selection box — already shipped)
- Font changes (Inter + Font Awesome already in place)
- Color palette overhaul (current dark charcoal + blue accent stays)
- Panel docking/layout restructuring

## Design

### Data structures

No new data structures. This is purely ImGui styling and layout code.

### Module touchpoints

- `Hamster-Wheel/src/Theme/HamsterTheme.cpp` — font size/weight variants, global spacing vars, style adjustments
- `Hamster-Wheel/src/Panels/PropertyEditor.cpp` — component section layout, field spacing, header styling
- `Hamster-Wheel/src/Panels/Hierarchy.cpp` — tree node styling, selection highlight, search bar
- `Hamster-Wheel/src/Panels/AssetBrowser.cpp` — grid layout with thumbnail cards and labels
- `Hamster-Wheel/src/EditorLayer.cpp` — viewport padding, zoom slider styling
- Possibly `Hamster-Wheel/src/Panels/FileBrowser.cpp` — if it shares layout patterns with AssetBrowser
- Possibly `Hamster-Wheel/src/Panels/Console.cpp` — if typographic hierarchy applies

### Lifecycle / control flow

No lifecycle changes. All modifications are in `OnImGuiUpdate()` render paths — purely how ImGui widgets are sized, spaced, and styled each frame.

### Edge cases

- Font size changes could cause text truncation in narrow panels — verify at minimum expected panel widths
- Asset browser grid must handle varying label lengths without overflow (long filenames, project names)
- Spacing changes must not break the property editor's input field alignment (X/Y fields need to stay horizontally paired)
- Hierarchy selection highlight must remain visible against the dark background at all tree depths

## Why this approach

The editor already has the foundational dark theme, Inter font, and Font Awesome icons from the editor-theme feature. Rather than a ground-up redesign, this pass refines what's already there — typographic weight, spacing, and one layout change (asset browser grid). This is the cheapest path to matching the mockup because the color palette and font stack don't need to change. The alternative — a full theme rewrite with a layout system abstraction — would be overkill for what's essentially spacing/sizing tweaks and one panel layout change.

## Risks / what could go wrong

- **ImGui font atlas rebuild**: adding font size/weight variants (e.g. bold headers) requires rebuilding the font atlas. If too many variants are added, atlas texture size grows and could cause a visible stutter on startup or exceed GPU texture limits on low-end hardware.
- **Hardcoded pixel sizes**: ImGui spacing/padding values are in pixels. If the editor is ever used on a high-DPI display, current hardcoded values will look too small. This pass will add more hardcoded values — acceptable for now but increases future DPI-scaling debt.
- **Asset browser grid performance with many items**: rendering large thumbnail icons in a grid could be slow if the project directory has hundreds of files. The current layout may not have this problem at current scale.
- **Spacing cascades**: changing padding/margins in one panel can shift the overall docking layout, causing other panels to resize unexpectedly. Each panel's spacing changes need to be tested in the full docked layout, not in isolation.

## Success criteria

- Run the editor with a project that has at least 3 entities with sprites and multiple asset files
- **Typography**: section headers (Transform, Sprite, etc.) are visually distinct from field labels — bolder and/or larger. Verifiable by screenshot comparison.
- **Property editor**: component sections have clear visual separation with consistent spacing. Fields are aligned.
- **Hierarchy**: selected entity has a clear highlight. Tree indentation is consistent. Overall styling feels polished.
- **Asset browser**: items display as a grid of cards with large icons/thumbnails and labels underneath. Grid reflows when panel is resized.
- **Level editor**: viewport has consistent edge padding. Zoom slider matches the mockup's pill/slider style.
- **No regressions**: all existing interactions (entity selection, drag, resize, context menus, play/stop) still work.

## Test extensions required

None. This is a pure additive UI/styling change with no logic, data, or API changes. Verification is visual — confirmed by running the editor and comparing against the mockup. The existing smoke test covers the C++/Python boundary and frame lifecycle, which this feature does not touch.
